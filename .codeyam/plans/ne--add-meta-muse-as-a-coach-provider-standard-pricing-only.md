## Summary

Add Meta's Muse Spark as a fourth bring-your-own-key coach provider, alongside Anthropic, OpenAI and Gemini, using Meta's **Standard** pricing only. Meta's Model API (`https://api.meta.ai/v1`) is OpenAI-compatible: Chat Completions takes the same `messages` array and the same `response_format: { type: "json_schema", json_schema: { name, schema, strict } }` shape, so the backend branch is the OpenAI path with a different host, model and error wording. Muse Spark 1.3 Standard costs $1.25 per million input tokens and $4.25 per million output, less than the current OpenAI and Gemini defaults. The goal is a cheaper option for users without weakening the privacy promise.

## Key Decisions

- **Standard only, never Contributor.** Meta's Contributor variants (`muse-spark-*-contributor`, about $0.10/$0.20 per million) are cheaper because Meta may use the prompts and responses to train its models. Otterpace's prompts carry Apple Health activity, the onboarding profile and journal entries, so Contributor would break the promise in the privacy policy and the App Review notes that this data goes only to the provider the user connected, to answer them. The backend pins a Standard model id and rejects any `*-contributor` id even when it comes from the env override, so a config change can't switch it on silently.
- **The provider is named "Meta", the model family "Muse".** That matches the existing pattern (`displayName` is the vendor, `modelFamily` is what answers): "Replies are generated by Muse".
- **The raw value is `meta`**, shared by `CoachProvider` (Swift) and `LlmProvider` (TypeScript), and sent in `x-ai-provider`.
- **Reuse the OpenAI request code instead of copying it.** Factor `completeOpenAI` into a shared `completeOpenAICompatible(provider, baseURL, model, apiKey, request)` that both OpenAI and Meta call. The prompt does not vary by provider (the invariant at the top of `api/_lib/llm.ts`).
- **No key-shape guess.** Meta's docs don't publish a key prefix. `detect(fromKey:)` keeps returning nil for an unrecognized shape, and the UI already asks the user to pick a provider in that case. If a stable prefix is confirmed at execution with a real key, add it after the `sk-ant-` check and before the generic `sk-` check.
- **Deploy the backend before the app.** An older backend's `isLlmProvider("meta")` is false, so `credentialsFromHeaders` returns null. The Vercel deploy must ship first. The app change goes in 1.0.5.
- **Default model `muse-spark-1.3`**, overridable via `COACH_MODEL_META` like the others.

## Implementation

### 1. Backend provider branch

**File**: `api/_lib/llm.ts`

- Add `"meta"` to `LlmProvider` and `PROVIDERS`.
- `MODELS.meta = process.env.COACH_MODEL_META || "muse-spark-1.3"`. In `modelFor`, refuse (throw at module load, or fall back to the default with a logged warning) any meta model id ending in `-contributor`.
- Extract the body of `completeOpenAI` into `completeOpenAICompatible`, parameterized by base URL, model, provider name and token-param name. OpenAI keeps `https://api.openai.com/v1` and `max_completion_tokens` with `OPENAI_MIN_COMPLETION_TOKENS`. Meta uses `https://api.meta.ai/v1/chat/completions`. **Confirm against Meta's Chat Completions reference at execution** whether it takes `max_completion_tokens` or `max_tokens`, and whether Muse's reasoning tokens count against the same budget (if so, give it the same headroom as OpenAI).
- Send `strict: true` for Meta too. Meta's strict mode requires a plain-object root, `additionalProperties: false` on every object, every property listed in `required`, and no `allOf`/`oneOf`. Check the coach, race-import and race-search schemas against those rules. They were already written for OpenAI strict mode, which has the same rules, so they should pass as is.
- `throwForStatus`: add the name "Meta" (replace the nested ternary with a `displayName(provider)` switch). `billingURL("meta")` is Meta's billing page on `dev.meta.ai`. **Confirm the exact path at execution.** Add Meta's out-of-credits wording to `isQuotaExhausted` once observed. Until then the generic `insufficient_quota` needles apply.
- `complete()` gets a `case "meta"`.

### 2. App provider case

**File**: `Sources/AppCore/Coach/CoachProvider.swift`

Add `case meta` with:
- `displayName` "Meta"
- `modelFamily` "Muse"
- `keyAccount` "coach-meta-key"
- `article` "a"
- `consoleURL` Meta's API-keys page on `dev.meta.ai` (**confirm the URL at execution**)
- `keyPlaceholder`: a neutral "Paste your Meta key" if no prefix is confirmed

`allNamesSentence` derives automatically, giving "Anthropic, OpenAI, Gemini, or Meta".

### 3. Hardcoded provider copy

**File**: `Sources/AppCore/SettingsView.swift` (line ~499)

Replace the hardcoded "Anthropic, OpenAI, or Gemini" with `CoachProvider.allNamesSentence`, the same fix the enum's comment describes for the race sheets.

### 4. Public copy and privacy

- **`site/privacy.html`**: add Meta to the provider list and state that Otterpace uses Meta's standard API terms, not its Contributor (training) mode.
- **`docs/ai-coach.md`, `docs/go-live-runbook.md`**: add Meta to the provider lists and to the "worth testing more than one provider" step.
- **App Store review notes** (version 1.0.5, set via the ASC API at submission, not in the repo): list Meta among the key options.
- **`Scripts/asc-setup-version.mjs`**: the What's New for 1.0.5 should say Buddy now works with a Meta (Muse) key.

### 5. Tests

- **`test/api/llm.test.ts`**:
  - Add `meta` to the provider lists at lines ~101 and ~107.
  - Assert that `complete({provider: "meta"})` posts to `api.meta.ai/v1/chat/completions` with the strict `json_schema` response format and the Bearer key.
  - Assert that a contributor model id from env is refused.
  - Assert that 401 maps to `invalid_key` and names "Meta", and that 429 maps to `rate_limited`.
- **`Tests/AppCoreTests/CoachProviderConsoleTests.swift`**: update `displayOrder.count` to 4, and add the Meta console URL.
- **`Tests/AppCoreTests/CoachProviderCopyTests.swift`**: update the expected sentence to "Anthropic, OpenAI, Gemini, or Meta".
- **`Tests/AppCoreTests/IntegrationModuleTests.swift`**: add Meta wherever per-provider properties are enumerated.

## Reused existing code

- `CoachProvider` from `Sources/AppCore/Coach/CoachProvider.swift` (glossary entry: `CoachProvider`), the single per-provider table on the app side
- `CoachProvider.allNamesSentence` and `keyRequirementCopy`, which already derive copy from the enum
- `completeOpenAI`, `throwForStatus`, `errorDetail`, `isQuotaExhausted` and `parseJsonReply` from `api/_lib/llm.ts`
- `credentialsFromHeaders` / `isLlmProvider` from `api/_lib/llm.ts`, which need no change beyond the provider list
- Existing schemas already follow OpenAI strict-mode rules, which match Meta's strict subset

## Scenarios to Demonstrate

- Settings → AI Coach with no key: the copy lists all four providers.
- Connecting a Meta key: the provider picker shows Meta, and the console link opens Meta's key page.
- Meta connected and active: "Replies are generated by Muse".
- Two providers connected (Anthropic + Meta), switching the active one.
- Race import sheet with Meta active: "uses your Meta API key".
